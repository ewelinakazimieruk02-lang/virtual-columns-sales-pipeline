# Virtual Columns & Sales Pipeline

Simple Python project using `pandas` for adding calculated columns to a DataFrame and cleaning raw sales data.

## Files in this repo
- `solution.py` – `add_virtual_column` function (Part 1)
- `pipeline.py` – script that cleans `sales.csv` and calculates total revenue per region (Part 2)
- `revenue_by_region.csv` – output generated by `pipeline.py`
- `test_virtual_column.py` – provided unit tests
- `test_solution_extra.py` and `test_pipeline.py` – my own tests for Part 1 and Part 2
- `sales.csv` – raw input data

## How to run

You need Python 3 with `pandas` and `pytest` installed:

```bash
pip install pandas pytest
```

To run the pipeline and generate `revenue_by_region.csv`:

```bash
python pipeline.py
```

To run all tests (13 in total) with one command:

```bash
pytest -v
```

## Assumptions

- **Multiple operations in `role`:** Since Part 2 needs `quantity * unit_price - discount`, I made `add_virtual_column` support more than one operator (`+`, `-`, `*`) in a single expression, following normal math order of operations.
- **Validation:** If the new column name, any existing column name in the DataFrame, or the formula itself is invalid, the function returns an empty DataFrame instead of raising an error. The original DataFrame is not changed.
- **Negative quantities:** There are 6 rows with negative `Quantity` values (all without a discount). I decided to keep them as product returns, so they reduce the revenue for their region. The `TOTAL` row at the bottom of the raw file (`37150`) also includes these negative numbers, which suggests they are meant to be counted as returns rather than dropped.
- **Output format:** In `revenue_by_region.csv`, regions are sorted alphabetically and revenue is rounded to 2 decimal places.

## Problems found in `sales.csv`

The raw file has **1,507 rows** (not counting the header). After cleaning, there are **1,500 clean order rows** left.

1. **Messy column names (header):** Names had uppercase letters and spaces, including a trailing space in `'Quantity '`. I stripped spaces, lowercased them, and replaced spaces with `_` (e.g. `unit_price`, `quantity`) so they work with `add_virtual_column`.
2. **Repeated header row (1 row):** One row in the middle of the file repeated the column headers (`Order ID,Region,...`). I removed it.
3. **`TOTAL` summary row (1 row):** The last row was a summary row with `Order ID = TOTAL`. I removed it so it wouldn't double-count the data.
4. **Exact duplicates (5 rows):** Five orders appeared twice with identical values. I removed the duplicate copies using `drop_duplicates()`.
5. **Inconsistent `Region` names (15 rows):** Some rows had extra spaces (like `' South'`, `'west  '`) or mixed letter case (like `'EAST'`, `'north'`). I cleaned them with `.str.strip().str.title()` so all rows map cleanly to the 5 regions (`Central`, `East`, `North`, `South`, `West`).
6. **Spaces inside `Quantity` numbers (4 rows):** Four large orders had a space as a thousands separator (e.g. `'1 762'`). I removed the space and converted the column to integers.
7. **Commas in `Unit Price` (7 rows):** Seven rows used a comma instead of a dot (e.g. `'59,00'`). I replaced `,` with `.` and converted the column to float.
8. **Missing `Unit Price` (4 rows):** Two rows for `Keyboard` and two for `Printer paper` had no price. Since each product in this file always has the exact same unit price (`89.00` for Keyboard, `21.00` for Printer paper), I filled the missing values using the price from other rows of the same product instead of dropping them.
9. **Empty `Discount` (963 rows, 959 after deduplication):** As described in the task, an empty discount means no discount, so I filled empty values with `0.0`.
10. **Negative `Quantity` (6 rows):** Values from `-2` to `-5`. Kept as returns (see Assumptions above).
